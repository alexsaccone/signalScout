# Domain docs

SignalScout uses a single root `GLOSSARY.md` and stores architecture
decision records (ADRs) in `docs/adr/`.

Before exploring the code, read the glossary and the relevant ADRs
when those files exist. Use the glossary's terms in tickets, tests,
and design proposals. Flag any proposal that conflicts with an ADR
and explain why the decision is worth reopening.

Add glossary entries and ADRs as terms and decisions are settled.
